# AI 文档编写与维护规范

本文档约束 `.agents/docs/` 中供 AI agent 检索和维护的项目知识。根 `README.md` 面向人类用户；源码是行为和接口的唯一权威。

## 读取顺序

对实现、行为、架构和调试问题，按以下顺序读取：

1. 从 [`.agents/docs/README.md`](../README.md) 选择最窄的主题入口。
2. 阅读目标文档中列出的仓库根相对路径和关键符号。
3. 打开源码核实事实；仅在需要时继续沿依赖或调用链扩展。
4. 若文档缺失、过时或与源码冲突，以源码为准并在同一工作单元修正文档。

不要默认读取整个目录，也不要为节省 token 跳过关键源码核实。

## 文档组织

- 根索引 `.agents/docs/README.md` 只负责顶层主题导航和阅读约定。
- 分类索引（当前为 `.agents/docs/modules/README.md`）负责其范围内的文档、源码入口和映射表。
- 叶子文档只讲一个可独立检索的主题；跨主题事实链接到唯一权威，不复制整张表、依赖图或长段落。
- 当一个索引超过约一屏、直接条目超过 10–14 个，且能形成至少两个各含多篇文档的主题时，再添加分类索引。
- 当一个叶子文档超过一屏并含至少两个可独立检索的主题时，改为目录、`README.md` 和多个叶子文档；否则保持单文件。
- 不创建空目录、空索引或只指向一篇文档的索引。

当前唯一权威如下：

| 事实 | 权威位置 |
|---|---|
| 模块、文档与源码入口映射 | `.agents/docs/modules/README.md` |
| 跨模块依赖、数据流和关键设计决策 | `.agents/docs/architecture.md` |
| CLI 契约 | `.agents/docs/cli.md` |
| `~/.di` 与分层配置 | `.agents/docs/di-home.md` |
| 发布验证状态与门槛 | `.agents/docs/typescript-validation.md` |
| 功能范围和路线图 | `.agents/docs/roadmap.md` |
| 文档写作和维护规则 | 本文档 |
| 面向人类的安装、运行和快速上手 | 根 `README.md` |

## 适合 AI 的写法

- 开头先给结论、职责或契约，再给实现细节和原因；避免仅重复标题的引言。
- 使用短段落和可扫描的小节；标题应直接描述可回答的问题，例如“模式选择”而不是“说明”。
- 并列规则使用列表；固定字段、参数或映射使用表格；有顺序的行为使用编号列表。
- 每个实现声明都写仓库根相对源码路径和关键符号，例如 `packages/agent/src/agent-loop.ts` 的 `runAgentLoop`。
- 只记录稳定、已核实的事实。临时调试笔记、整段源码拷贝和无结论的实现日志不进入长期文档。
- 链接文本使用仓库相对路径（如 [`.agents/docs/cli.md`](../cli.md)）；链接目标使用从当前文件可解析的相对路径。
- 用明确的条件和结果描述约束：说明谁负责、何时触发、失败时如何处理。避免“可能”“相关”等不指向实现的措辞。

## 变更规则

新增、修改、移动或删除代码，且影响行为、接口、数据结构、调用关系或架构时，检查并同步更新相关文档。

移动或重命名文档时，同一改动必须完成：

1. 更新父索引和全部跨文档链接。
2. 更新根 `README.md`、测试夹具、脚本和源码注释中的路径引用。
3. 保持上表的唯一权威，不留下重复的规范描述。

新增文档时，放入最窄的既有索引；只有满足“文档组织”的拆分条件才新增分类。不要为了未来可能的内容预建结构。

## 完成前检查

- 每篇正式文档均能从 `.agents/docs/README.md` 逐级到达。
- 文档链接、源码路径、测试路径和关键符号有效。
- 文档事实与源码一致，且不存在第二份相互竞争的权威描述。
- 本次移动没有留下旧文档路径引用，也没有意外修改文档范围之外的内容。
- 按改动风险运行相关构建、类型检查或测试，并如实记录结果。
